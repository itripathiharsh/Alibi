# 04 — API Specification

The **source of truth is the generated OpenAPI 3.1 document** (`backend/openapi.json`, regenerated by `make openapi`).
This document defines conventions and the endpoint catalogue; schemas live in Pydantic models and must match the descriptions here.

## 1. Conventions
- Base path `/api/v1`. JSON UTF-8. snake_case fields. Timestamps ISO-8601 with offset (server returns UTC `Z`). Dates `YYYY-MM-DD` interpreted in user tz.
- Auth: `Authorization: Bearer <access_token>` (except `/auth/login`, `/auth/refresh`, `/auth/setup`, `/auth/signup`, `/health/*`, `/s/*`).
- Device: `X-Device-Id: <uuid>` required on authenticated requests from apps (used by sync and audit).
- Idempotency: all `POST` creating resources accept client-supplied `id` (UUIDv7) **or** `Idempotency-Key` header; repeating returns the original result with `200` instead of `201`.
- Optimistic concurrency: `PATCH`/`DELETE` on syncable entities accept `If-Match: <version>`; mismatch → `409 version_conflict` with current entity in body.
- Pagination: `?limit=50&cursor=<opaque>` → `{ "items": [...], "next_cursor": "..." | null }`. Max limit 200.
- Filtering: explicit query params (no generic query language).
- Rate limits: auth 5/15 min failed; AI endpoints 30/min; share viewer 60/min/IP. `429` with `Retry-After`.

## 2. Error format (RFC 7807, `application/problem+json`)
```json
{ "type": "https://alibi.local/errors/validation_error", "title": "Validation failed", "status": 422,
  "code": "validation_error", "detail": "deadline_at must be in the future or null",
  "errors": [{"field": "deadline_at", "message": "..."}], "request_id": "..." }
```

## 3. Error code catalogue
| code | status | meaning |
|------|--------|---------|
| validation_error | 422 | Body/query invalid |
| unauthenticated | 401 | Missing/invalid/expired token |
| token_reused | 401 | Refresh token reuse; family revoked |
| forbidden | 403 | Valid auth, not allowed |
| not_found | 404 | Missing or not owned (never reveal existence) |
| version_conflict | 409 | If-Match mismatch |
| invalid_transition | 409 | Illegal status change |
| conflict | 409 | Resource conflicts with existing state, such as an active repeat rule for the same task |
| dependency_cycle | 409 | Would create cycle |
| proposal_stale | 409 | Schedule inputs changed since proposal |
| ai_unavailable | 503 | No provider reachable for the op (client must degrade) |
| ai_invalid_output | 502 | Provider returned unusable output after repair |
| rate_limited | 429 | |
| payload_too_large | 413 | Upload > limit |
| storage_quota_exceeded | 413 | Total stored files would exceed the configured quota (hosted default 250 MB, ADR-020) |
| share_expired / share_revoked | 410 | |

### 4.2 Auth (FR-AUTH)
| Method | Path | Body → Response |
|---|---|---|
| GET | /auth/setup-status | `{needs_setup: bool}` |
| POST | /auth/setup | `{email, password, display_name}` → 201 user; only when 0 users else 403 |

| POST | /auth/login | `{email, password, device:{id,name,platform}}` → `{access_token, refresh_token, expires_in, user}` (web: refresh in cookie) |

| POST | /auth/logout | revokes current device family |
| GET | /auth/me | user + settings |

Password policy: ≥ 6 chars, checked against the bundled common-password blacklist; no composition rules.

### 4.3 Categories, projects, tags
CRUD: `GET/POST /categories`, `PATCH/DELETE /categories/{id}` (system: no delete → 409), same for `/projects`, `/tags`.
Category body: `{name, sharing_class, external_ai_allowed, color}`.

### 4.4 Tasks (FR-TASK)
| Method | Path | Notes |
|---|---|---|
| POST | /tasks/capture | `{id, raw_input, origin, captured_at, category_hint?}` → 201 `{task, extraction|null, extraction_status}`; `?parse=sync|async|none` (default sync with 8 s budget, falls back to async) |
| POST | /tasks/brain-dump | FR-TASK-022, ADR-028. `{text}` (1–4000 chars) → `{items[{title, source_text, deadline_at, deadline_phrase, deadline_kind, bucket: today|this_week|later|anytime, priority, estimate_minutes, category, suggested_at, time_source: said|suggested}]. Titles are AI-corrected (spelling, grammar, structure) when cloud AI ran (`mode: ai`); suggested slots stay inside the user's `settings.day_start`/`day_end` (default 09:00–21:00). Task responses and sync payloads also carry `original_deadline_at`., mode: ai|rules, ai_status: used|not_opted_in|server_disabled|unavailable, provider}`. Saves nothing; the device saves the items the user keeps. Dates come only from the rules parser on phrases found in the text. |
| GET | /tasks/{id}/extraction | latest extraction proposal |
| POST | /tasks/{id}/extraction/decision | `{accepted_fields{}, corrected_fields{}, rejected_fields[]}` → updated task; emits prediction feedback |
| POST | /tasks | full create `{id, title, description?, category_id?, project_id?, priority?, deadline_at?, deadline_kind?, estimate_user_min?, origin, origin_ref?, tags?[], subtasks?[]}` |
| GET | /tasks | `view=today|upcoming|backlog|completed|all`, `status`, `category_id`, `project_id`, `tag`, `q`, `from`, `to`, `sort`, pagination |
| GET | /tasks/{id} | includes subtasks, tags, dependencies, evidence summary, time totals, latest predictions |
| PATCH | /tasks/{id} | partial; If-Match |
| POST | /tasks/{id}/status | `{status, at?, completion_note?, evidence_ids?[]}`; validates transitions |
| POST | /tasks/{id}/reschedule | `{new_deadline_at?, reason?}` → increments reschedule_count, logs event |
| DELETE | /tasks/{id} | soft delete; `POST /tasks/{id}/restore`; `DELETE /tasks/{id}?hard=true` only from trash |
| GET | /tasks/{id}/events | activity history (paginated) |
| GET | /tasks/daily-kickoff | up to three SQL-ranked open-task suggestions; no task changes are written |
| GET | /tasks/end-of-day | local-day completion count and unfinished due, scheduled, or in-progress tasks |
| POST | /tasks/{id}/end-of-day-action | `{action: tomorrow|backlog|cancel}`; only applies the user's explicit choice; tomorrow uses the next configured workday and logs a reschedule event |
| POST/PATCH/DELETE | /tasks/{id}/subtasks[/{sid}] | `POST /tasks/{id}/subtasks/reorder {ids[]}` |
| POST/DELETE | /tasks/{id}/dependencies[/{dep_id}] | cycle check |
| GET | /recurrences?task_id= | Active recurrence rules for the authenticated user; optional task filter |
| POST | /recurrences | `{task_id, frequency: daily|weekly|monthly, interval: 1..52, starts_at, until_at?}`; explicitly creates a repeat rule from the selected task; duplicate active rule for the same task → 409 |
| DELETE | /recurrences/{id} | Stops future generation; already generated tasks remain |

Recurring tasks are generated ahead by nightly maintenance only after the user creates a rule. Generated instances copy the saved task fields and never create calendar work blocks. The schedule and capture flows require the user to accept proposed extracted fields or proposed calendar blocks before those changes are applied.

### 4.6 Evidence & uploads
`POST /tasks/{id}/evidence` (multipart file or JSON link/text; MIME allow-list: pdf, png, jpg, webp, docx, xlsx, txt, md, csv; ≤ 25 MB in local mode, **≤ 2 MB in hosted mode with a 250 MB total quota → 413 `payload_too_large` / `storage_quota_exceeded`**, ADR-020; limits come from config), `GET /evidence/{id}/download` (auth, `Content-Disposition: attachment`), `DELETE /evidence/{id}`.

### 4.7 Voice (FR-TASK-002, FR-AI-010)
`POST /voice/transcribe` multipart `audio` (m4a/aac/webm/wav ≤ 2 min / 10 MB), `language?` → `{transcript, language, duration_s, engine, confidence}`.
`POST /voice/capture` = transcribe + `/tasks/capture` in one call with `{id}`.
Hosted mode (ADR-020): these endpoints return 503 `ai_unavailable` unless external AI is enabled (then `engine=groq`); audio is never persisted. The Android client normally transcribes on-device and calls `/tasks/capture` directly with origin `voice`.

### 4.18 Organizations (FR-ORG)
All routes require authentication except the safe invite preview. IDs are authorized on the server; clients cannot supply a member's user ID to broaden access.
| Method | Path | Notes |
|---|---|---|
| POST | /organizations | Create organization; caller becomes owner |
| GET | /organizations/mine | Current account's memberships and consent state |
| GET | /organizations/{org_id} | Organization details for active members |
| GET | /organizations/{org_id}/members | Owner/team-lead list; only active members are included |
| POST | /organizations/{org_id}/invites | Owner creates a team-lead or member invite; token is returned once |
| GET | /organizations/{org_id}/invites | Owner/team-lead list of pending invite metadata only; raw tokens are never recoverable |
| GET | /organization-invites/{token} | Safe invite preview: organization name, role, expiry; no member information |
| POST | /organization-invites/{token}/accept | Authenticated user explicitly accepts professional-only sharing (`professional_sharing_consent=true`); consent version and timestamp recorded |
| POST | /organizations/{org_id}/consent | Member explicitly opts in; starts a new consent window |
| POST | /organizations/{org_id}/consent/revoke | Revoke consent immediately; existing org queries stop returning the member |
| POST | /organizations/{org_id}/leave | Member leaves; owner must transfer ownership first |
| POST | /organizations/{org_id}/invites/{invite_id}/revoke | Owner/team lead revokes an unused invite |
| GET | /organizations/{org_id}/overview | SQL aggregates filtered to active, consented professional data |
| GET | /organizations/{org_id}/members/{membership_id}/activity | Professional task titles/status/times only; no descriptions, notes, evidence, or other sharing classes |

Professional score uses the existing documented score formula applied only to `sharing_class='professional'` rows. Insufficient samples return null with an explanatory state.

## 5. API acceptance criteria
- AC-API-1 Every endpoint has request/response Pydantic models, appears in OpenAPI with examples and error responses.
- AC-API-2 Schemathesis property-based run against OpenAPI: 0 server errors (5xx) and 0 schema violations.
- AC-API-3 Every authenticated endpoint returns 401 without token and 404 for another user's resource (ownership test generated per route).
- AC-API-4 Idempotency test: each create endpoint called twice with same id → one row, second call 200.
- AC-API-5 `If-Match` mismatch → 409 with current entity.
- AC-API-6 No endpoint returns `api_key`, `password_hash`, `token_hash` fields (response-model audit test).
- AC-API-7 Generated TS client compiles and CI fails when stale.
